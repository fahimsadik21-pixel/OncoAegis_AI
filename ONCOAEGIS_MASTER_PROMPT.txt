============================================================
PROJECT VISION
============================================================

OncoAegis AI is an adaptive multimodal cancer detection and analysis assistant. It is not a simple cancer-classification demo and it must not use a generic LLM as a cancer detector.

One external assistant will coordinate multiple independent specialist systems:

1. Medical imaging specialists
   - CT, ultrasound, MRI, PET, mammography, and histopathology
   - organ identification
   - lesion detection and localization
   - segmentation
   - lesion measurement and volume calculation
   - morphology and risk analysis

2. Document and clinical-intelligence specialists
   - PDF, TXT, radiology, pathology, biopsy, laboratory, blood, and genetic reports
   - evidence extraction
   - structured summarization
   - cancer-related finding extraction

3. Multimodal fusion
   - combine image evidence, document evidence, and clinical evidence
   - identify agreement, uncertainty, and conflicts
   - never hide contradictory evidence

============================================================
MANDATORY MEDICAL SAFETY RULES
============================================================

Imaging alone must never be reported as confirmed cancer. Use terms such as suspicious lesion, suspicious for malignancy, high-risk appearance, indeterminate, or requires expert review.

Only pathology or biopsy-confirmed evidence may be treated as confirmed malignancy evidence. If imaging and pathology conflict, output an explicit evidence-conflict status and withhold a definitive conclusion.

Every result must include evidence, uncertainty, model/task provenance, and a clear research-only/expert-review disclaimer where appropriate.

============================================================
REQUIRED EXECUTION ORDER AFTER DATASET DOWNLOAD
============================================================

For each new dataset, follow this order and stop if a validation fails:

1. Inspect the actual folder tree and archive.
2. Record dataset metadata in the registry: name, source, modality, organ, task, annotation type, size, license, local path, status, and intended model.
3. Build or select a dataset adapter that converts it into the common StandardMedicalSample format.
4. Validate file counts, labels, masks, dimensions, spacing, orientation, corrupted files, and missing pairs.
5. Split by patient/case before creating image or slice rows. Verify zero patient overlap between train, validation, and test.
6. Implement modality-specific preprocessing:
   - CT: DICOM/NIfTI loading, orientation, spacing, HU conversion where applicable, windowing, clipping, normalization, and resampling.
   - MRI: modality-aware normalization and volume handling.
   - Ultrasound: grayscale/RGB handling, resizing, normalization, mask cleanup, and safe augmentation.
   - Dermoscopy/histopathology: image normalization, mask/label validation, and class balancing without leakage.
7. Implement augmentation only on the training split.
8. Create DataLoaders with deterministic seeds and reproducible configuration.
9. Train the smallest suitable specialist baseline first.
10. Evaluate with task-appropriate metrics:
    - segmentation: Dice, IoU, sensitivity/recall, precision, HD95 when available
    - detection: sensitivity, precision, F1, AP, localization error
    - classification: accuracy, balanced accuracy, macro F1, per-class precision/recall, confusion matrix, AUROC when valid
11. Save checkpoints, configuration, metrics JSON, confusion matrices, qualitative overlays, and failure examples.
12. Add a safe inference adapter and API route only after offline evaluation passes.
13. Run unit tests, smoke tests, and a real local sample through the endpoint.
14. Update the checkpoint/progress document with completed work, exact commands, metrics, limitations, and the next milestone.
